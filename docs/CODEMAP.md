## Host and Profile entry points

- [Backend project](../src/Jularr.Backend/Jularr.Backend.csproj): class library; [Frontend Program](../src/Jularr.Frontend/Program.cs): the only web host. Backend host registration: [README](../README.md#backend-im-gemeinsamen-host).
- [ServiceApi.cs](../src/Jularr.Backend/Service/Core/ServiceApi.cs): configuration-based host registration, Backend-owned data source, service DI, endpoint discovery, parameter/body binding and antiforgery.
- [ServiceEndpointAttribute.cs](../src/Jularr.Backend/Service/Core/ServiceEndpointAttribute.cs): class-level API opt-in; unmarked services stay internal, System services cannot be exposed.
- [ServiceExceptionHandler.cs](../src/Jularr.Backend/Service/Core/ServiceExceptionHandler.cs): central sanitized ProblemDetails, including binding and data validation failures.
- [ServiceError.cs](../src/Jularr.Backend/Service/Core/ServiceError.cs): shared API/Razor error codes and resource keys; Frontend `JularrPage` owns form feedback.
- [ReadUiTextsV1.cs](../src/Jularr.Backend/Service/Public/Localization/V1/ReadUiTextsV1.cs), [ReadUiLocalesV1.cs](../src/Jularr.Backend/Service/Public/Localization/V1/ReadUiLocalesV1.cs): canonical Public reads for Razor/API; SQL resolves fallback and aggregates the complete language pack. [UiLocalizationCache.cs](../src/Jularr.Backend/Service/Public/Localization/V1/UiLocalizationCache.cs) is passive caching; [registration](../src/Jularr.Backend/Service/Core/Localization/UiLocalizationRegistration.cs) synchronizes English declarations at startup.
- [UiLocalizationLogic.cs](../src/Jularr.Backend/Logic/Localization/UiLocalizationLogic.cs): source sync and canonical description/translation mutations; [host contract and gaps](../README.md#gemeinsamer-postgresql-textkatalog).
- [Admin localization services](../src/Jularr.Backend/Service/Admin/Localization/V1/UiMessageServices.cs), [versioned catalog contracts](../src/Jularr.Backend/Data/Admin/Localization/V1/UiMessages.cs): paged editable reads and Owner description/manual translation updates.
- [Admin account services](../src/Jularr.Backend/Service/Admin/Account/V1/AccountServices.cs), [versioned account contracts](../src/Jularr.Backend/Data/Admin/Account/V1/Accounts.cs): directory, approval and complete name/role/status replacement through Account Logic; last write wins. The canonical Account writer retains an enabled Owner; Session Logic revokes obsolete credential proofs in the same transaction.
- [AccountProfileServices.cs](../src/Jularr.Backend/Service/Admin/Account/V1/AccountProfileServices.cs), [AccountProfileLogic.cs](../src/Jularr.Backend/Logic/Account/AccountProfileLogic.cs): existing profile access assignment/removal, retained owner link and transactional session invalidation.
- [AccountSessionServices.cs](../src/Jularr.Backend/Service/Admin/Account/V1/AccountSessionServices.cs): Owner account-scoped session reads/revocation through the canonical Session writer.
- [UiLocaleServices.cs](../src/Jularr.Backend/Service/Admin/Localization/V1/UiLocaleServices.cs), [UiLocales.cs](../src/Jularr.Backend/Data/Admin/Localization/V1/UiLocales.cs): Owner language registry editing; canonical field format and localization writer.
- [ProviderServices.cs](../src/Jularr.Backend/Service/Admin/Provider/V1/ProviderServices.cs), [Providers.cs](../src/Jularr.Backend/Data/Admin/Provider/V1/Providers.cs): existing provider registry enablement, not connection/capability management.
- [InstanceSettingsServices.cs](../src/Jularr.Backend/Service/Admin/Instance/V1/InstanceSettingsServices.cs), [InstanceSettings.cs](../src/Jularr.Backend/Data/Admin/Instance/V1/InstanceSettings.cs): Owner name/language reads and version-checked edits; [InstanceLogic.cs](../src/Jularr.Backend/Logic/Instance/InstanceLogic.cs) owns mutations and enabled-locale locking. [Instance.sql](../database/Instance.sql) is a fresh singleton baseline, not a migration.
- [InstanceModuleServices.cs](../src/Jularr.Backend/Service/Admin/Instance/V1/InstanceModuleServices.cs), [InstanceModuleLogic.cs](../src/Jularr.Backend/Logic/Instance/InstanceModuleLogic.cs): Owner module editing and configuration locks. [ReadInstanceCapabilitiesV1.cs](../src/Jularr.Backend/Service/User/Instance/V1/ReadInstanceCapabilitiesV1.cs) combines implemented Library/Requests/Playback functions with verified grants; [ReadInstancePresentationV1.cs](../src/Jularr.Backend/Service/Public/Instance/V1/ReadInstancePresentationV1.cs) exposes only name/default language.
- [ProfileServices.cs](../src/Jularr.Backend/Service/User/Profile/V1/ProfileServices.cs): the one read and one update; permissions and orchestration.
- [ServiceGate.cs](../src/Jularr.Backend/Service/Core/ServiceGate.cs): DB-role-based account/Profile and Admin grants; MediaManager is limited to manual media/Requests/Wanted. Role changes are revalidated in the write transaction.
- [ProfileSelectionServices.cs](../src/Jularr.Backend/Service/User/Profile/V1/ProfileSelectionServices.cs): membership-scoped paged list and session profile selection.
- [SessionServices.cs](../src/Jularr.Backend/Service/User/Session/V1/SessionServices.cs): live owned session list, revocation and logout.
- [ProfileLogic.cs](../src/Jularr.Backend/Logic/Profile/ProfileLogic.cs): entity locking, business validation and the canonical writer.
- [SessionLogic.cs](../src/Jularr.Backend/Logic/Session/SessionLogic.cs): mutable session authorization locks in the write transaction.
- [AuthenticationServices.cs](../src/Jularr.Backend/Service/Public/Authentication/V1/AuthenticationServices.cs), [PlexAuthenticationServices.cs](../src/Jularr.Backend/Service/Public/Authentication/V1/PlexAuthenticationServices.cs): Public auth state, login, registration requests and Plex orchestration.
- [SetupServices.cs](../src/Jularr.Backend/Service/Public/Setup/V1/SetupServices.cs), [Setup.cs](../src/Jularr.Backend/Data/Public/Setup/V1/Setup.cs): Public first-Owner availability and creation, field/password confirmation validation; Account Logic owns permanent bootstrap closure and Session Logic signs in atomically.
- [SessionAuthentication.cs](../src/Jularr.Backend/Service/Core/SessionAuthentication.cs), [SessionCookieEvents.cs](../src/Jularr.Backend/Service/Core/SessionCookieEvents.cs): request-level database-backed cookie verification.
- [AccountLogic.cs](../src/Jularr.Backend/Logic/Account/AccountLogic.cs), [PlexAuthenticationLogic.cs](../src/Jularr.Backend/Logic/Authentication/PlexAuthenticationLogic.cs): credentials, canonical account/profile creation, external identity and single-use completion.
- [PlexClient.cs](../src/Jularr.Integrations/Logic/Plex/PlexClient.cs): bounded external protocol calls and user-scoped library access. [Data/Plex](../src/Jularr.Integrations/Data/Plex): explicit protocol results; [ProviderUnavailableException.cs](../src/Jularr.Integrations/Data/Common/ProviderUnavailableException.cs): shared integration error. [Integrations project](../src/Jularr.Integrations/Jularr.Integrations.csproj): Data/Logic class library without Backend dependencies or a host; [AuthenticationOptions.cs](../src/Jularr.Backend/Service/Core/AuthenticationOptions.cs): Backend-owned authentication policy/configuration.
- [ProviderLogic.cs](../src/Jularr.Backend/Logic/Provider/ProviderLogic.cs): enabled-provider lookup and configuration lock; [ProviderData.cs](../src/Jularr.Backend/Data/Logic/Provider/ProviderData.cs): typed neutral lookup data.

## Contracts and persistence

- [Storage services](../src/Jularr.Backend/Service/Admin/Storage/V1): bounded Owner configuration/catalog reads, protected connection saves and explicit external mount actions. [Storage data](../src/Jularr.Backend/Data/Admin/Storage/V1) contains versioned inputs/results.
- [StorageMountLogic.cs](../src/Jularr.Backend/Logic/Storage/StorageMountLogic.cs) owns canonical configuration writes; [Storage.sql](../database/Storage.sql) is the fresh physical-connection baseline, separate from pending LibraryRoots.
- [NasMountClient.cs](../src/Jularr.Integrations/Logic/Nas/NasMountClient.cs), [MountManager.cs](../src/Jularr.MountHelper/MountManager.cs): private socket integration and Linux mount execution; [WakeOnLanClient.cs](../src/Jularr.Integrations/Logic/Nas/WakeOnLanClient.cs) sends magic packets.
- [Library root services](../src/Jularr.Backend/Service/Admin/Library/V1/LibraryRootServices.cs), [LibraryRootLogic.cs](../src/Jularr.Backend/Logic/Library/LibraryRootLogic.cs): Owner library paths per connection without overlaps; [Library.sql](../database/Library.sql) holds roots, inventory, tracks and Operations.
- [Library file services](../src/Jularr.Backend/Service/Admin/Library/V1/LibraryFileServices.cs): inventory reads with path suggestions, manual identification, scan queue and operation list. [MediaAssetLogic.cs](../src/Jularr.Backend/Logic/Media/MediaAssetLogic.cs) owns Work/unit/edition/version/asset creation; [WorkUnitType.cs](../src/Jularr.Backend/Data/Enums/Media/WorkUnitType.cs) is the canonical unit rule per media type.
- [OperationWorker.cs](../src/Jularr.Backend/Service/System/Operation/OperationWorker.cs), [System operation services](../src/Jularr.Backend/Service/System/Operation/V1/OperationServices.cs): hosted background scans through request-free System services; [StoredFileLogic.cs](../src/Jularr.Backend/Logic/Library/StoredFileLogic.cs) and [OperationLogic.cs](../src/Jularr.Backend/Logic/Operation/OperationLogic.cs) write inventory and operation state; [MediaPathParser.cs](../src/Jularr.Backend/Logic/Library/MediaPathParser.cs) suggests titles/units.
- [StorageFileSystem.cs](../src/Jularr.Integrations/Logic/Storage/StorageFileSystem.cs), [MediaProbeClient.cs](../src/Jularr.Integrations/Logic/Media/MediaProbeClient.cs): bounded folder/file enumeration without links or traversal and `ffprobe` analysis. [Storage runtime](STORAGE_RUNTIME.md) owns deployment/limits; [schema alignment](SCHEMA_SNAPSHOT_ALIGNMENT.md) records snapshot coverage.

- [User request services](../src/Jularr.Backend/Service/User/Request/V1/RequestServices.cs), [Admin request services](../src/Jularr.Backend/Service/Admin/Request/V1/RequestServices.cs), [Wanted services](../src/Jularr.Backend/Service/Admin/Wanted/V1/WantedServices.cs): profile-scoped language intent, bounded status queues, moderation and manual pause/resume.
- [AcquisitionRequestLogic.cs](../src/Jularr.Backend/Logic/Acquisition/AcquisitionRequestLogic.cs), [WantedLogic.cs](../src/Jularr.Backend/Logic/Acquisition/WantedLogic.cs): idempotent creation, Open decisions and atomic shared whole-Work targets. [Acquisition.sql](../database/Acquisition.sql): explicit fresh baseline after Account/Media.
- TMDB metadata: [TmdbClient.cs](../src/Jularr.Integrations/Logic/Tmdb/TmdbClient.cs), [WorkMetadata.cs](../src/Jularr.Backend/Service/Admin/Media/WorkMetadata.cs) (key from the Providers registry, instance language), [metadata services](../src/Jularr.Backend/Service/Admin/Media/V1/WorkMetadataServices.cs) (search, import, refresh) and [WorkMetadataLogic.cs](../src/Jularr.Backend/Logic/Media/WorkMetadataLogic.cs) (identities, provider titles, seasons and episodes); wanted series refresh daily.
- Arr+ core: [connection services](../src/Jularr.Backend/Service/Admin/Acquisition/V1/AcquisitionConnectionServices.cs) (Owner, protected keys, test), [WantedAcquisition.cs](../src/Jularr.Backend/Service/Admin/Wanted/WantedAcquisition.cs) (the one search, ranking and grab path for manual and automatic acquisition), [Wanted search services](../src/Jularr.Backend/Service/Admin/Wanted/V1/WantedSearchServices.cs), [System acquisition services](../src/Jularr.Backend/Service/System/Acquisition/V1/AcquisitionServices.cs) and [AcquisitionWorker.cs](../src/Jularr.Backend/Service/System/Acquisition/AcquisitionWorker.cs) (due searches with backoff, SABnzbd monitoring, path mapping, hardlink/copy import and assignment). Pure ranking ported from dev: [ReleaseParser.cs](../src/Jularr.Backend/Logic/Acquisition/ReleaseParser.cs), [SearchPlanner.cs](../src/Jularr.Backend/Logic/Acquisition/SearchPlanner.cs), [VideoReleaseJudge.cs](../src/Jularr.Backend/Logic/Acquisition/VideoReleaseJudge.cs), [ReleaseSelection.cs](../src/Jularr.Backend/Logic/Acquisition/ReleaseSelection.cs); Series searches run per season (fully aired and empty: pack; otherwise episodes) with [EpisodeScope](../src/Jularr.Backend/Service/Admin/Wanted/WantedAcquisition.cs); DML in [DownloadLogic.cs](../src/Jularr.Backend/Logic/Acquisition/DownloadLogic.cs) (shared "missing aired episode" rule) and [AcquisitionConnectionLogic.cs](../src/Jularr.Backend/Logic/Acquisition/AcquisitionConnectionLogic.cs). Clients: [NewznabClient.cs](../src/Jularr.Integrations/Logic/Newznab/NewznabClient.cs), [SabnzbdClient.cs](../src/Jularr.Integrations/Logic/Sabnzbd/SabnzbdClient.cs), [StorageFileTransfer.cs](../src/Jularr.Integrations/Logic/Storage/StorageFileTransfer.cs).

- [WorkServices.cs](../src/Jularr.Backend/Service/Admin/Media/V1/WorkServices.cs), [Works.cs](../src/Jularr.Backend/Data/Admin/Media/V1/Works.cs): manual Work creation, paged catalog, detail and version-checked title edits for Owner/MediaManager.
- [WorkLogic.cs](../src/Jularr.Backend/Logic/Media/WorkLogic.cs): shared canonical Work/title writer; preserves independent localized/provider title sources.
- [MediaServices.cs](../src/Jularr.Backend/Service/User/Media/V1/MediaServices.cs), [Media.cs](../src/Jularr.Backend/Data/User/Media/V1/Media.cs): persisted Work detail, stored availability and session-profile-scoped watchlist reads/updates. [WatchlistLogic.cs](../src/Jularr.Backend/Logic/Media/WatchlistLogic.cs) changes personal state only.
- [Media.sql](../database/Media.sql): fresh catalog/title/watchlist baseline after Account.sql; no active installation or migration. Module/profile media visibility, effective metadata locale and inventory/playback remain unintegrated.

- [PlaybackServices.cs](../src/Jularr.Backend/Service/User/Playback/V1/PlaybackServices.cs), [Playback.cs](../src/Jularr.Backend/Data/User/Playback/V1/Playback.cs): canonical playback item, capability-based PlaybackPlan with on-demand wake, authorized range streaming through `IFileOutput` in [ServiceApi.cs](../src/Jularr.Backend/Service/Core/ServiceApi.cs) and progress reports; conversions serve a VOD playlist and on-demand segments. [PlaybackTranscodes.cs](../src/Jularr.Backend/Service/User/Playback/PlaybackTranscodes.cs) runs one paced FFmpeg job per session (restart on seek, process stop when idle or far ahead, cache expiry after six idle hours or at session end, job budget, software fallback) through [MediaTranscoder.cs](../src/Jularr.Integrations/Logic/Media/MediaTranscoder.cs); [MediaOptions.cs](../src/Jularr.Backend/Service/Core/MediaOptions.cs) holds tool paths and limits. [PlaybackLogic.cs](../src/Jularr.Backend/Logic/Playback/PlaybackLogic.cs) owns direct-play and conversion decisions, sessions and MediaProgress; [Playback.sql](../database/Playback.sql) is the fresh baseline.
- [Profile.cs](../src/Jularr.Backend/Data/User/Profile/V1/Profile.cs): public Profile parameters, inputs and result.
- [ProfileSelection.cs](../src/Jularr.Backend/Data/User/Profile/V1/ProfileSelection.cs), [Session.cs](../src/Jularr.Backend/Data/User/Session/V1/Session.cs): versioned selection/session contracts with hidden credential transport.
- [Data/Public/Authentication/V1](../src/Jularr.Backend/Data/Public/Authentication/V1): versioned Public auth contracts; [BaseParameters.cs](../src/Jularr.Backend/Data/Common/BaseParameters.cs), [BaseResponse.cs](../src/Jularr.Backend/Data/Common/BaseResponse.cs): service contract roles over BaseData.
- [Data/Public/Localization/V1](../src/Jularr.Backend/Data/Public/Localization/V1): versioned locale list and language-pack parameters/results; there is no parallel consumer catalog interface.
- [Data/Logic](../src/Jularr.Backend/Data/Logic): neutral entity lookups/mutations and session authentication data. [AccountProfileData.cs](../src/Jularr.Backend/Data/Logic/Account/AccountProfileData.cs) is the shared Account/Profile association; [AccountParameters.cs](../src/Jularr.Backend/Data/Logic/Account/AccountParameters.cs) scopes account reads.
- [ProfileFields.cs](../src/Jularr.Backend/Data/Fields/Profile/ProfileFields.cs), [AccountSessionFields.cs](../src/Jularr.Backend/Data/Fields/Account/AccountSessionFields.cs): canonical Profile/account-session fields.
- [Data/Fields/Account](../src/Jularr.Backend/Data/Fields/Account): Account, AccountProfile, credential, challenge and external-login fields; names match the singular schema entity.
- [Data/Enums](../src/Jularr.Backend/Data/Enums): enums grouped by Account, Service and Sql owner.
- [UiLocaleFields.cs](../src/Jularr.Backend/Data/Fields/Localization/UiLocaleFields.cs), [ProviderFields.cs](../src/Jularr.Backend/Data/Fields/Provider/ProviderFields.cs): required locale/provider catalog fields.
- [InstanceSetupStateFields.cs](../src/Jularr.Backend/Data/Fields/Setup/InstanceSetupStateFields.cs): canonical singleton bootstrap fields; Account Logic owns their transactional closure.
- [BaseData.cs](../src/Jularr.Backend/Data/Common/BaseData.cs): cached field validation, same-name property merging, Id-based list merging and partial/list JSON binding.
- [DataField.cs](../src/Jularr.Backend/Data/Fields/DataField.cs): C#-named field classes and their PostgreSQL types; [DataFieldAttribute.cs](../src/Jularr.Backend/Data/Common/DataFieldAttribute.cs): required/optional and length overrides.
- [Service.cs](../src/Jularr.Backend/Service/Core/Service.cs): invocation lifecycle, operation hooks and shared transaction.
- [ServiceRuntime.cs](../src/Jularr.Backend/Service/Core/ServiceRuntime.cs): internal gate, SqlContext factory and central runtime binding. Logic, SQL infrastructure and the Plex client are internal; consumers use services and Data contracts.
- [SqlContext.cs](../src/Jularr.Backend/Infrastructure/Sql/SqlContext.cs): one connection/transaction, shared ordinary reads and Logic execution; [SqlExecutor.cs](../src/Jularr.Backend/Infrastructure/Sql/SqlExecutor.cs): explicit typed binding/mapping, no injected auth IDs; [LogicContext.cs](../src/Jularr.Backend/Infrastructure/Sql/LogicContext.cs): direct Logic calls and guarded short batches.
- [SqlDatabase.cs](../src/Jularr.Backend/Infrastructure/Sql/SqlDatabase.cs): internal shared data-source owner and host disposal.
- [SqlParams.cs](../src/Jularr.Backend/Data/SqlParams.cs): typed object binding with cached field metadata and compiled getters.
- [Pagination.cs](../src/Jularr.Backend/Data/Pagination.cs), [SqlStatement.cs](../src/Jularr.Backend/Infrastructure/Sql/SqlStatement.cs): shared PageRequest and bounded page results, including direct JSON deserialization of items/page/pageSize through the same bounds; [ListService.cs](../src/Jularr.Backend/Service/Core/ListService.cs): once-per-invocation page hook.
- [Account.sql](../database/Account.sql): the single fresh Account/Profile/auth/session/localization baseline; [schema scope](../database/README.md). [UiTranslationFields.cs](../src/Jularr.Backend/Data/Fields/Localization/UiTranslationFields.cs) and [UiTranslationStatusType.cs](../src/Jularr.Backend/Data/Enums/Localization/UiTranslationStatusType.cs) own translation fields/catalog values.

## Focused tests

All tests are in [Jularr.Backend.Tests](../tests/Jularr.Backend.Tests).

- Profile behavior/rollback: `ProfileReferenceVerticalTests.cs`; authorization/HTTP: `ProfileServiceGateTests.cs`.
- Invocation, internal visibility and PostgreSQL-free consumer signatures: `ServiceFoundationTests.cs`, `ServiceArchitectureTests.cs`.
- Backend-owned data-source lifecycle, direct/API calls, API opt-in, public binding and common errors: `ServiceApiTests.cs` (no database).
- Connection/transaction and SQL binding: `SqlContextTests.cs`, `SqlExecutorTests.cs`; metadata: `DataFieldTests.cs`.
- Account/auth schema and catalog/field consistency: `AccountSchemaTests.cs`.
- Shared localization, startup idempotence, manual protection, fallback, cache invalidation and rollback: `UiLocalizationTests.cs`.
- Owner account updates, last-Owner concurrency, session invalidation and Razor editor: `AdminAccountTests.cs`; catalog authorization, stale edits and encoded Razor forms: `AdminLocalizationTests.cs`.
- Account assignments and Owner session revocation: `AdminAccountTests.cs`; language creation/editing/fallback and Razor: `AdminLocaleTests.cs`; provider enablement/auth availability and forms: `AdminProviderTests.cs`.
- Login/cookies, pending registration, Plex grants, browser proof, expiry and replay: `AuthenticationTests.cs` (isolated PostgreSQL and controlled provider responses).
- First-Owner form, rollback, concurrency, session issuance and permanent bootstrap closure: `SetupTests.cs`.
- Manual catalog/title edits, role restriction, stale updates, personal list isolation and real Razor forms: `MediaTests.cs`.
- Instance settings, Owner-only access, enabled locales, stale edits and real Razor forms: `InstanceSettingsTests.cs`.
- Real module gating, data retention, All/Any/write locks, public branding/default locale and capability-driven Razor navigation: `InstanceCapabilitiesTests.cs`.
- Request isolation/idempotence, bounded reads, moderation rollback/shared targets and real Razor forms/module gating: `RequestTests.cs`.
- Connections, manual search/grab, queue progress, completed-download import, release-fault retry, automatic search, TMDB import, season packs and episodes, selection gates, Newznab parsing and Razor pages: `AcquisitionTests.cs` (fake indexer and SABnzbd over a test HTTP handler).
- Storage configuration, protected credentials, Owner access, Setup/Admin forms, socket communication and command boundaries: `StorageTests.cs`.
- Playback plans, range streaming, resume/completion, foreign sessions, module gate, sleeping storage, delivery/conversion decisions, FFmpeg arguments, playlists and HLS segment serving: `PlaybackTests.cs`; set `JULARR_TEST_FFMPEG` to an FFmpeg 7+ executable to also run the real transcoding/seek/budget test.
- Library paths, scans, missing/offline handling, identification, versions, restart recovery, local paths, wake, browsing, parser, probe parsing and Razor forms: `LibraryTests.cs`.
- Real Razor forms, antiforgery, language settings, selection rotation, session revocation and logout: `FrontendAuthenticationTests.cs`; requires built Frontend assets.
- `Infrastructure/TestPostgres.cs`: explicit isolated PostgreSQL fixture; never use the application database.

## Not integrated

Remaining Setup steps, metadata beyond TMDB movies/series, Anime absolute numbering and the remaining media types in Arr+, profile editing, NAS probes/reconnect/Synology, on-demand wake, email verification, 2FA/WebAuthn completion,
PIN selection, old Android/TV consumers, full Profile management, per-media/profile visibility, further module capabilities and full custom branding.
This reference backend does not complete Phase B or replace an active installation.
