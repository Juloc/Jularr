## Host and Profile entry points

- [Backend project](../src/Jularr.Backend/Jularr.Backend.csproj): class library; [Workers project](../src/Jularr.Workers/Jularr.Workers.csproj): hosted background work that only runs System services ([WorkerRegistration.cs](../src/Jularr.Workers/WorkerRegistration.cs); timer workers share [PeriodicWorker.cs](../src/Jularr.Workers/PeriodicWorker.cs)); [Frontend Program](../src/Jularr.Frontend/Program.cs): the only web host. Backend host registration: [README](../README.md#backend-im-gemeinsamen-host).
- [ServiceApi.cs](../src/Jularr.Backend/Service/Core/ServiceApi.cs): configuration-based host registration, Backend-owned data source, service DI, endpoint discovery, parameter/body binding and antiforgery.
- [ServiceEndpointAttribute.cs](../src/Jularr.Backend/Service/Core/ServiceEndpointAttribute.cs): class-level API opt-in; unmarked services stay internal, System services cannot be exposed.
- [ServiceExceptionHandler.cs](../src/Jularr.Backend/Service/Core/ServiceExceptionHandler.cs): central sanitized ProblemDetails, including binding and data validation failures.
- [ServiceError.cs](../src/Jularr.Backend/Service/Core/ServiceError.cs): shared API/Razor error codes and resource keys; Frontend `JularrPage` owns form feedback.
- [ReadUiTextsV1.cs](../src/Jularr.Backend/Service/Public/Localization/V1/ReadUiTextsV1.cs), [ReadUiLocalesV1.cs](../src/Jularr.Backend/Service/Public/Localization/V1/ReadUiLocalesV1.cs): canonical Public reads for Razor/API; SQL resolves fallback and aggregates the complete language pack. [UiLocalizationCache.cs](../src/Jularr.Backend/Service/Public/Localization/V1/UiLocalizationCache.cs) is passive caching; [registration](../src/Jularr.Backend/Service/Core/Localization/UiLocalizationRegistration.cs) synchronizes English declarations at startup.
- [UiLocalizationLogic.cs](../src/Jularr.Backend/Logic/Localization/UiLocalizationLogic.cs): source sync and canonical description/translation mutations; [host contract and gaps](../README.md#gemeinsamer-postgresql-textkatalog).
- [Admin localization services](../src/Jularr.Backend/Service/Admin/Localization/V1/UiMessageServices.cs), [versioned catalog contracts](../src/Jularr.Backend/Data/Admin/Localization/V1/UiMessages.cs): paged editable reads and Owner description/manual translation updates.
- [Admin account services](../src/Jularr.Backend/Service/Admin/Account/V1/AccountServices.cs), [versioned account contracts](../src/Jularr.Backend/Data/Admin/Account/V1/Accounts.cs): directory, approval and complete name/role/status replacement through Account Logic; last write wins. The canonical Account writer retains an enabled Owner; Session Logic revokes obsolete credential proofs in the same transaction.
- [AccountProfileServices.cs](../src/Jularr.Backend/Service/Admin/Account/V1/AccountProfileServices.cs), [AccountProfileLogic.cs](../src/Jularr.Backend/Logic/Account/AccountProfileLogic.cs): existing profile access assignment/removal, retained owner link and transactional session invalidation.

- [UiLocaleServices.cs](../src/Jularr.Backend/Service/Admin/Localization/V1/UiLocaleServices.cs), [UiLocales.cs](../src/Jularr.Backend/Data/Admin/Localization/V1/UiLocales.cs): Owner language registry editing; canonical field format and localization writer.
- [ProviderServices.cs](../src/Jularr.Backend/Service/Admin/Provider/V1/ProviderServices.cs), [Providers.cs](../src/Jularr.Backend/Data/Admin/Provider/V1/Providers.cs): existing provider registry enablement, not connection/capability management.
- [InstanceSettingsServices.cs](../src/Jularr.Backend/Service/Admin/Instance/V1/InstanceSettingsServices.cs), [InstanceSettings.cs](../src/Jularr.Backend/Data/Admin/Instance/V1/InstanceSettings.cs): Owner name/language reads and version-checked edits; [InstanceLogic.cs](../src/Jularr.Backend/Logic/Instance/InstanceLogic.cs) owns mutations and enabled-locale locking. [Instance.sql](../database/Instance.sql) is a fresh singleton baseline, not a migration.
- [InstanceModuleServices.cs](../src/Jularr.Backend/Service/Admin/Instance/V1/InstanceModuleServices.cs), [InstanceModuleLogic.cs](../src/Jularr.Backend/Logic/Instance/InstanceModuleLogic.cs): Owner module editing and configuration locks. [ReadInstanceCapabilitiesV1.cs](../src/Jularr.Backend/Service/User/Instance/V1/ReadInstanceCapabilitiesV1.cs) returns the caller's verified grants and the usable enabled modules; the Frontend checks them with `UiText.Can` and names page offers once in [Abilities.cs](../src/Jularr.Frontend/Framework/Abilities.cs); [ReadInstancePresentationV1.cs](../src/Jularr.Backend/Service/Public/Instance/V1/ReadInstancePresentationV1.cs) exposes only name/default language.

- Media visibility: views in [Media.sql](../database/Media.sql); switches in [InstanceMediaServices.cs](../src/Jularr.Backend/Service/Admin/Instance/V1/InstanceMediaServices.cs), Owner blocks in [ProfileMediaAccessServices.cs](../src/Jularr.Backend/Service/Admin/Account/V1/ProfileMediaAccessServices.cs), personal hiding in [ProfileMediaServices.cs](../src/Jularr.Backend/Service/User/Profile/V1/ProfileMediaServices.cs); writes in [MediaCategoryLogic.cs](../src/Jularr.Backend/Logic/Media/MediaCategoryLogic.cs).
- [ServiceGate.cs](../src/Jularr.Backend/Service/Core/ServiceGate.cs): DB-role-based account/Profile and Admin grants; MediaManager is limited to manual media/Requests/Wanted. Role changes are revalidated in the write transaction.
- [ProfileSelectionServices.cs](../src/Jularr.Backend/Service/User/Profile/V1/ProfileSelectionServices.cs): membership-scoped paged list and session profile selection; a PIN-protected profile is selected through `VerifyProfilePinV1`, which commits failed attempts before reporting them. PIN rules, hashing and the five-failure/one-minute lockout: [ProfilePinLogic.cs](../src/Jularr.Backend/Logic/Profile/ProfilePinLogic.cs); the profile sets or removes its PIN (`UpdateProfilePinV1`, `RemoveProfilePinV1`), the Owner resets a forgotten one (`ResetProfilePinV1`). The `Profiles` instance module (off by default) switches multiple profiles: off, the view `SelectableProfiles` ([Instance.sql](../database/Instance.sql)) offers each account only its main profile (own first, then the oldest), sessions pick it automatically, PINs do not apply and creation, deletion and PIN services are unavailable; capability `CanManageProfiles` hides their UI. An account creates up to ten own profiles (`CreateProfileV1`); deleting a profile (`DeleteProfileV1`, owner account, active profile) removes its progress, lists and links, cancels its open requests, keeps the others with the account (they still count against its request limit) and returns its sessions to the picker ([ProfileLogic.cs](../src/Jularr.Backend/Logic/Profile/ProfileLogic.cs)).
- [SessionServices.cs](../src/Jularr.Backend/Service/User/Session/V1/SessionServices.cs): live owned session list, revocation and logout.
- [ProfileLogic.cs](../src/Jularr.Backend/Logic/Profile/ProfileLogic.cs): entity locking, business validation and the canonical writer.
- [SessionLogic.cs](../src/Jularr.Backend/Logic/Session/SessionLogic.cs): mutable session authorization locks and canonical expiry renewal in the write transaction.
- [AuthenticationServices.cs](../src/Jularr.Backend/Service/Public/Authentication/V1/AuthenticationServices.cs), [PlexAuthenticationServices.cs](../src/Jularr.Backend/Service/Public/Authentication/V1/PlexAuthenticationServices.cs): Public auth state, login, registration requests and Plex orchestration.
- [SetupServices.cs](../src/Jularr.Backend/Service/Public/Setup/V1/SetupServices.cs), [Setup.cs](../src/Jularr.Backend/Data/Public/Setup/V1/Setup.cs): Public first-Owner availability and creation, field/password confirmation validation; Account Logic owns permanent bootstrap closure and Session Logic signs in atomically.
- [SessionAuthentication.cs](../src/Jularr.Backend/Service/Core/SessionAuthentication.cs), [SessionCookieEvents.cs](../src/Jularr.Backend/Service/Core/SessionCookieEvents.cs): request-level database-backed cookie verification; half-life renewal commits the locked DB session before refreshing the persistent cookie. [ServiceApi.cs](../src/Jularr.Backend/Service/Core/ServiceApi.cs) registers the stable Data-Protection context and optional persistent key directory.
- [AccountLogic.cs](../src/Jularr.Backend/Logic/Account/AccountLogic.cs), [PlexAuthenticationLogic.cs](../src/Jularr.Backend/Logic/Authentication/PlexAuthenticationLogic.cs): credentials, canonical account/profile creation, external identity and single-use completion.
- [PlexClient.cs](../src/Jularr.Integrations/Logic/Plex/PlexClient.cs): bounded external protocol calls and user-scoped library access. [Data/Plex](../src/Jularr.Integrations/Data/Plex): explicit protocol results; [ProviderUnavailableException.cs](../src/Jularr.Integrations/Data/Common/ProviderUnavailableException.cs): shared integration error. [Integrations project](../src/Jularr.Integrations/Jularr.Integrations.csproj): Data/Logic class library without Backend dependencies or a host; [AuthenticationOptions.cs](../src/Jularr.Backend/Service/Core/AuthenticationOptions.cs): Backend-owned authentication policy/configuration.
- [ProviderLogic.cs](../src/Jularr.Backend/Logic/Provider/ProviderLogic.cs): enabled-provider lookup and configuration lock; [ProviderData.cs](../src/Jularr.Backend/Data/Logic/Provider/ProviderData.cs): typed neutral lookup data.

- [NasMountClient.cs](../src/Jularr.Integrations/Logic/Nas/NasMountClient.cs), [MountManager.cs](../src/Jularr.MountHelper/MountManager.cs): private socket integration and Linux mount execution; [WakeOnLanClient.cs](../src/Jularr.Integrations/Logic/Nas/WakeOnLanClient.cs) sends magic packets.
- [Library root services](../src/Jularr.Backend/Service/Admin/Library/V1/LibraryRootServices.cs), [LibraryRootLogic.cs](../src/Jularr.Backend/Logic/Library/LibraryRootLogic.cs): Owner library paths per connection without overlaps; [Library.sql](../database/Library.sql) holds roots, inventory, tracks and Operations.
- [Library file services](../src/Jularr.Backend/Service/Admin/Library/V1/LibraryFileServices.cs): inventory reads with path suggestions, manual identification, scan queue and the confirmed rename ([LibraryRenameLogic.cs](../src/Jularr.Backend/Logic/Library/LibraryRenameLogic.cs)); [LibraryNaming.cs](../src/Jularr.Backend/Logic/Library/LibraryNaming.cs) is the one library layout for imports and renames. [MediaAssetLogic.cs](../src/Jularr.Backend/Logic/Media/MediaAssetLogic.cs) owns Work/unit/edition/version/asset creation; [WorkUnitType.cs](../src/Jularr.Backend/Data/Enums/Media/WorkUnitType.cs) is the canonical unit rule per media type; [MediaSubtype.cs](../src/Jularr.Backend/Data/Enums/Media/MediaSubtype.cs) the subtypes (Anime, Manga, Light Novel) of their parent types. Imports go to the Wanted target's chosen library, else to one of the Work's type and enabled subtype (`ReadImportRootAsync`).
- Named sections over a Work's unit ranges (UnitGroups module): [WorkUnitGroupServices.cs](../src/Jularr.Backend/Service/Admin/Media/V1/WorkUnitGroupServices.cs) and [WorkUnitGroupLogic.cs](../src/Jularr.Backend/Logic/Media/WorkUnitGroupLogic.cs); the availability read names each unit's section (chapters follow their volume).
- Home layout per profile (HomeLayout module): [HomeLayoutServices.cs](../src/Jularr.Backend/Service/User/Home/V1/HomeLayoutServices.cs) and [HomeLayoutLogic.cs](../src/Jularr.Backend/Logic/Profile/HomeLayoutLogic.cs) keep the order and visibility of the home shelves (`ProfileHomeShelves`); Discover builds its local shelves in that order, Settings edits it.
- [Activity services](../src/Jularr.Backend/Service/Admin/Activity/V1/ActivityServices.cs): scans and downloads as Activity (running), To-Do (waiting imports with `AttentionKey`, undismissed failures) and History; retry/dismiss in [OperationLogic.cs](../src/Jularr.Backend/Logic/Operation/OperationLogic.cs).
- [OperationWorker.cs](../src/Jularr.Workers/OperationWorker.cs), [System operation services](../src/Jularr.Backend/Service/System/Operation/V1/OperationServices.cs): hosted background scans and backups through request-free System services; [StoredFileLogic.cs](../src/Jularr.Backend/Logic/Library/StoredFileLogic.cs) and [OperationLogic.cs](../src/Jularr.Backend/Logic/Operation/OperationLogic.cs) write inventory and operation state; [MediaPathParser.cs](../src/Jularr.Backend/Logic/Library/MediaPathParser.cs) suggests titles/units.
- [StorageFileSystem.cs](../src/Jularr.Integrations/Logic/Storage/StorageFileSystem.cs), [MediaProbeClient.cs](../src/Jularr.Integrations/Logic/Media/MediaProbeClient.cs): bounded folder/file enumeration without links or traversal and `ffprobe` analysis. [Storage runtime](STORAGE_RUNTIME.md) owns deployment/limits; [schema alignment](SCHEMA_SNAPSHOT_ALIGNMENT.md) records snapshot coverage.

- [User request services](../src/Jularr.Backend/Service/User/Request/V1/RequestServices.cs), [Admin request services](../src/Jularr.Backend/Service/Admin/Request/V1/RequestServices.cs), [Wanted services](../src/Jularr.Backend/Service/Admin/Wanted/V1/WantedServices.cs): profile-scoped language intent, bounded status queues, moderation and manual pause/resume. Request rules ([RequestRuleServices.cs](../src/Jularr.Backend/Service/Admin/Request/V1/RequestRuleServices.cs), [RequestRuleLogic.cs](../src/Jularr.Backend/Logic/Acquisition/RequestRuleLogic.cs)): rule profiles with limit per rolling period, approval, allowed media and the qualities requesters may choose, one default; accounts inherit the default or an assigned rule and override single values; the view `EffectiveRequestRules` resolves them. A new request locks its account, checks media, offered quality and limit (repeated intent does not count) and is approved at once for the Owner or an automatic rule; a new Wanted target takes the requested quality, an existing one keeps its own (one version and profile per Work).
- [AcquisitionRequestLogic.cs](../src/Jularr.Backend/Logic/Acquisition/AcquisitionRequestLogic.cs), [WantedLogic.cs](../src/Jularr.Backend/Logic/Acquisition/WantedLogic.cs): idempotent creation, Open decisions and atomic shared whole-Work targets. [Acquisition.sql](../database/Acquisition.sql): explicit fresh baseline after Account/Media.
- User discovery: [Discover services](../src/Jularr.Backend/Service/User/Discover/V1/DiscoverServices.cs) (TMDB feeds with a short shared cache, search over local Works and TMDB, a provider title, request from a provider title through canonical Work resolution) and [Library services](../src/Jularr.Backend/Service/User/Library/V1/LibraryServices.cs) (local catalog, Continue for video, audio, books and comics with the read share). Overview, poster and backdrop are `WorkMetadataFacts`.

- Calendar (module `Calendar`): [ReadCalendarV1](../src/Jularr.Backend/Service/User/Calendar/V1/CalendarServices.cs) lists released units (episodes, volumes, tracks by `WorkUnits.ReleasedOn`) of the profile's watchlisted, requested or owned Works and Works without units (movies) by `Works.ReleasedOn`, TMDB's first release date, for up to 62 days; tests `CalendarTests.cs`.
- Collections (module `Collections`): [CollectionLogic.cs](../src/Jularr.Backend/Logic/Media/CollectionLogic.cs) keeps a profile's hand-picked collections (Works in the order added, only Works the profile sees) and smart collections (a saved filter: type, subtype, release years, only in the library, only unfinished); [collection services](../src/Jularr.Backend/Service/User/Collection/V1/CollectionServices.cs) read one static query for both kinds; tests `CollectionTests.cs`. Franchises from provider collections follow.
- Notifications (module `Notifications`): [NotificationLogic.cs](../src/Jularr.Backend/Logic/Notification/NotificationLogic.cs) writes a profile's notices where things happen (request decisions in `AcquisitionRequestLogic`, arrivals for requesters and failed downloads for managers in `DownloadLogic`, storage that stays offline for Owners in the reconnect service); muted kinds stay silent and an unread notice about the same subject counts up. [Notification services](../src/Jularr.Backend/Service/User/Notification/V1/NotificationServices.cs) read, count, mark read and mute; tests `NotificationTests.cs`.

- Book sources (R2b): [SourceCatalog.cs](../src/Jularr.Backend/Data/Enums/Acquisition/SourceCatalog.cs) (honest catalog: ready, needs account, planned, reference only) with [source catalog services](../src/Jularr.Backend/Service/Admin/Acquisition/V1/SourceCatalogServices.cs) (read, set up keyless sources); [DirectSources.cs](../src/Jularr.Backend/Service/Admin/Wanted/V1/DirectSources.cs) searches and downloads Gutenberg, OPDS ([OpdsClient.cs](../src/Jularr.Integrations/Logic/Opds/OpdsClient.cs), instance login sent to the catalog origin only) and Anna's Archive ([AnnasArchiveClient.cs](../src/Jularr.Integrations/Logic/AnnasArchive/AnnasArchiveClient.cs), member key only to its API; without a key the public slow download with its countdown up to 90 s, otherwise attention `source_manual_link`: a person passes the check in their own browser and pastes the HTTPS file link through Activity or, with instance setting `UsersConfirmSources` plus account switch `MayConfirmSources`, through their own request; waiting downloads are not asked again); releases keep their `SourceUrl`. [DirectDownload.cs](../src/Jularr.Integrations/Logic/Common/DirectDownload.cs): bounded redirects, one renewal of expired signed links, gates go to `ISourceGateResolver` whose production implementation never passes them (attention `source_gate`); test overrides live only in `SourceTests.cs`. A person's Anna's Archive file link is stored on the operation (`AttentionUrl` page to open, `SourceLinkUrl` pasted link; an expired link returns to the person) and fetched through [PublicNetwork.cs](../src/Jularr.Integrations/Logic/Common/PublicNetwork.cs), which connects to public addresses only.
